# Rule Index (Derived Document; Defines No Rules)

> **This file defines no rules**; it only registers "rule ID ↔ canonical sentence ↔ authoritative doc ↔ code anchor ↔ machine check".
> Rule bodies follow the "authoritative doc", which all live inside this framework (`Framework/`); the old framework has been a pure historical archive since 2026-11-12 and is no longer referenced by any script or document.
>
> Conventions:
>
> - **Domain invariants** use the **R / W / S** series; **engineering constraints** use the **E** series.
> - Every rule must have a **canonical sentence that stays verbatim-stable on one line**; **any change to either the ID or the canonical sentence counts as L2** (see DesignPrinciples.en.md §3).
> - Order for adding a rule: first write the canonical sentence in the authoritative doc and tag the ID → register it in this table → then write the code anchor → then add the machine check.
> - `machine check` = `—` means it can currently only be covered by manual review; never write "checked" for "unchecked".
> - Do not mint new parallel prefixes: S / W / R serve only the original five-axes domain; E carries only engineering constraints and does not participate in S / W / R mapping.
> - When definitions conflict, the "Authoritative doc" column of this table is the sole arbitration; rule ownership follows ModuleRules.en.md §12 "Document Map".
> - For the historical origins and trade-offs of W / R / S, see each module's `DesignDecisions.en.md`; this table serves current maintenance only.
