### What this mod does

Storage mods traditionally suffer from missing features, redundant features, bugs and poor compatibility. This mod solves it by consolidating digital storage into **five vanilla engine paths**, patched uniformly at the **vanilla function API** level, fully decoupled from specific work types and workbench lists:

| Path | Meaning |
|---|---|
| Visible | The vanilla resource bar, `ListerThings`, thingGrid can see the hyper stock (mirror projections) |
| Readable | One quantity semantics: total − reserved = available; virtual / preserved channels accounted separately |
| Findable | Recipes, bills, hauling, trading and loading all draw ingredients from the space |
| Takeable | Withdrawal runs as a reserve → materialize → deliver transaction; full rollback on failure, the ledger never drifts |
| Storable | Vanilla haul-job exits are rewritten uniformly; the space acts as a storage cell / container |

**Dual-channel design**:

- **Virtual channel**: rebuildable items (resources, products, food, chunks) are recorded as counts + stack-average state;
- **Preserved channel**: unrebuildable things (corpses, minified buildings, quality/color/art/charged gear, studiable items) keep the true body, returned as-is.

**Gameplay entry**: build a **Hyperdimensional Space Core** (linkable with Anchors and Stabilizers), unlock via research, or implant a **Hyperdimensional Space Chip** into a colonist.

### Architecture

Eight production assemblies + three test projects, ports-and-adapters (hexagonal) architecture with one-way dependencies:

```
Bootstrap (composition root: seven-step startup, injects 11 host interfaces)
    │
    ▼
Vanilla (all Harmony patches: mirror projection / endpoints / job interception / UI / trade & transport)
    │  host implementations
    ▼
Rules (decision layer: channel / capacity / availability + process layer: withdrawal transactions / reservations / returns) ──► Core (the single ledger, pure data, testable standalone)
    │                                                                                                          │
    ▼                                                                                                          ▼
Contracts (11 host interfaces + shared data contracts) ◄────────────────────────────────────────────────────────┘
    ▲
    │
Api (public five-axis facade) ◄── ThirdModCompat (8 adapters)        Diag (self-check / compatibility reports)
```

Key constraints (violating any of these is treated as an architecture defect):

- **Core depends on nothing** — the ledger is pure data + pure ledger rules; no pathfinding, no UI, no patches, so it is unit-tested outside the game;
- **No Harmony patches outside Vanilla** — all vanilla intrusion is concentrated in `SDS.Vanilla/Install/`;
- **Third-party adapters are bridges only** — they never pick endpoints, count quantities or create jobs; everything forwards to the single implementation;
- **All static state is registered** — cross-save static caches register `ResetStatics` and are fully reset on new game / load.

None of this is enforced by goodwill — every constraint has rule IDs, authoritative docs, code anchors and machine checks (below).

### 这个 MOD 做什么

传统存储类 MOD 的痛点：功能不足 / 功能冗余 / bug 多 / 兼容性差。本 MOD 的解法是把「数字存储」收敛为原版引擎的五条路径，并按**原版函数 API** 统一补丁，与具体工作类型、具体工作台清单完全解耦：

| 路径 | 含义 |
|---|---|
| 看得见 | 原版资源条、ListerThings、thingGrid 能看到超维库存（镜像投影） |
| 读的准 | 数量口径唯一：账面 − 预留 = 可用量，虚拟/保真通道分开核算 |
| 找得到 | 配方、账单、搬运、交易、装载的寻料全部接入超维空间 |
| 拿得到 | 取货走预留 → 物化 → 交付三段事务，失败整笔回滚，绝不丢账 |
| 存得到 | 原版搬运派活出口统一改写，超维空间可作为存储区格子/容器 |

**双通道设计**：

- **虚拟通道**：可重建物品（原材料、制成品、食物、块堆）只记数量与堆平均状态；
- **保真通道**：不可重建物（尸体、缩装建筑、带品质/颜色/艺术/充能的装备、研究进度物）封存真身，原样取出。

**玩法入口**：建造「超维空间核心」（可附连锚点与稳固装置）、研究解锁、殖民者植入「超维空间芯片」后随身可用。

### 架构

八个生产程序集 + 三个测试工程，端口-适配器（六边形）架构，依赖方向单向：

```
Bootstrap（组合根：七步启动，注入 11 个宿主接口）
    │
    ▼
Vanilla（全部 Harmony 补丁：镜像投影 / 端点 / Job 拦截 / UI / 运输贸易）
    │  宿主实现
    ▼
Rules（判定层：通道 / 容量 / 可用量 + 流程层：取货事务 / 预留 / 回充） ──► Core（唯一账本，纯数据，可独立测试）
    │                                                            │
    ▼                                                            ▼
Contracts（11 个宿主接口 + 公共数据契约） ◄──────────────────────────┘
    ▲
    │
Api（第三方五轴门面） ◄── ThirdModCompat（8 个适配器）        Diag（自检 / 兼容报告）
```

关键约束（违反即视为架构缺陷）：

- **Core 不反向依赖任何模块**：账本是纯数据 + 纯账本规则，不寻路、不写 UI、不打补丁，因此可以脱离游戏单独跑测试；
- **Vanilla 之外禁止出现 Harmony 补丁**：对原版的全部侵入集中在 `SDS.Vanilla` 的 `Install/`；
- **第三方适配器只做桥**：不允许自行选端点、算数量、建 Job，全部转发唯一实现；
- **静态状态全部登记**：跨存档静态缓存统一注册 `ResetStatics`，新档 / 读档彻底重置。

以上约束不是口头约定——每一条都有规则 ID、权威文档、代码锚点与机器校验（见下）。

- `0Harmony.dll` 默认从 `<仓库上级>\.mod\harmony\1.7\Assemblies\` 解析，可用 `-p:HarmonyDir=<路径>` 覆盖；
- 测试工程会把游戏 DLL 复制到输出目录运行（部分用例直接使用原版类型），因此同样需要 `-p:GameDir=`。
